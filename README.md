# キャラ人格調律工房（Persona Tuning Workshop）

AIチャットアプリ向けのキャラクター人格を、スライダーで「具体的な行動規則」に変換する設計ツールです。

- 公開ページ：https://nyuriwossan.github.io/persona-tuning-workshop/
- 単一HTML・外部AI API不要・登録不要（設定はブラウザ内に保存）
- iPhone Safari 優先

## できること

0. **人格の構成方式（v0.6.0）**：「人格調律」の一番上で、**単独人格**（関係段階を設けず、一定の人格を設計）と**段階変化型**（初期・信頼成立後・関係深化後の3段階。従来の方式で既定）を切り替えられる。詳しくは下の「単独人格モード」。
1. **人格調律**：人格項目（23軸）はすべて任意。最上部の一覧か各カテゴリの中で使う項目にチェックを入れ（新規は全項目OFFから）、選んだ項目だけを 5段階のスライダーで調整する。使っていない項目は控えめな色の行で並び、いつでもチェックできる（外しても値は残る）。「初期」「信頼成立後」「関係深化後」を設定し、変えたくない軸は固定できる。口調プリセット（8種）と一人称・二人称も設定。
2. **人格プリセット**：基本人格12種（高慢・尊大、クーデレ、ツンデレなど）と愛情スタイル8種（甘々、溺愛、無口な溺愛など）、ギャップ10種（v0.8.0。段階変化型のみ）。適用前に「今の値 → 提案」を確認でき、使用中で値が違う項目は既定で今の値を残す。固定中の項目は変えない。基本人格と愛情スタイルは別の項目を変えるので重ねて使える。関係での変わり方（徐々に軟化／大きなギャップ／変化は控えめ）を選べ、直前の適用は取り消せる。
3. **関係段階の作り方**：自動提案（初期から後の2段階を一度だけ提案）／連動調整（初期を動かすと段階差を保って追従）／完全個別。
4. **関係・反応**：信頼が成立する／深まる／後退する条件、恋愛感情（信頼とは別軸）、If-Then の行動規則。
   - **キャラクターの自律性（v0.7.0）**：「関係・反応」の「キャラクターの自律性」で、OOC・メタ発言・地の文によるキャラクターの行動・心情・人格の強制指定を抑える規則を出力できる（初期値OFF）。詳しくは下の「キャラクターの自律性」。
5. **人格の試着**：16の状況で、3段階の会話例を並べて比較。恋愛感情の段階、ほかの人物と{{user}}への態度の違いも比べられる（v0.8.0）。口調・呼称を試しに変えられる。会話例は Markdown で書き出せる。
   - **v0.8.0 の追加**：人格形成の背景、ギャップ設計、恋愛感情・関係段階の状態遷移、プロンプトの配置（重要度優先形式・末尾への再掲）、設定集（ロアブック）用テキスト。詳しくは下の「v0.8.0 の新機能」。
6. **Markdown出力**：上部の「出力先」で、共通Markdown（汎用）／ZETA／Zetter／Talelynx／チャチャ／Plaitoon を切り替えられる（v0.5.0。ZETA・Zetterは v0.8.0）。予定文字数に合わせて詳細度を自動選択。共通部分は一度だけ、段階の変化は差分で書く。出力するのは選んだ人格項目だけ。プリセット名は標準では出さず、今の値から作った行動規則を出力する。
   - 出力する節を選べる：話し方・呼称／基本人格・核・3段階の振る舞い／関係の進展条件（初期→信頼成立後・信頼成立後→関係深化後・後退の3種を個別に）／恋愛感情の条件・反応／If-Then（規則ごとにも選択）。新規は話し方と人格だけON。OFFでも設定は保持する。
   - 未設定の行（条件0件など）や空の見出しは出力しない。各節の横に、今の詳細度での増減字数を表示する。

## v0.8.0 の新機能

どれも任意です。使わなければ、出力・動作は v0.7.0 と同じです（回帰テストで1文字単位で確認）。設定を自動で上書き・削除することはなく、矛盾があるときは警告だけを出します。

### 人格形成の背景（「人格調律」）

- なぜその人格になったのかを、**原体験 → 信念・価値観 → 現在の人格 → 具体的な行動** の順に書きます。過去の傷だけでなく、肯定的な原体験・教育環境・成功体験・価値観を形づくった人物なども扱えます。何件でも登録できます。
- 1件の項目：原体験・過去の出来事／形成された信念・価値観／現在の人格への影響／特定の状況や話題に対する反応／関係深化によって変化し得る部分／他者への開示条件／出力（人格設定に出力・設定集用・出力しない）／優先度。すべて任意です。
- 原体験のプリセット26種（対人関係7・家庭・成育環境7・成功・失敗・責任6・価値観の形成6）。選ぶと、編集できる候補の文章が入ります。**経験から特定の人格が必然的に形成されるという扱いはせず、人格スライダーの値も変えません。**
- 出力例：

```
## 人格形成の背景
- 過去の経験は、現在の言動の理由として反映する。経験の詳細は、開示条件が物語内で成立するまで自分から語らない。
- 原体験：信頼していた人物に裏切られた経験がある。
- 信念：言葉よりも、継続的な行動を信用する。
- 人格への影響：他者の好意を慎重に受け止め、相手の誠実さを時間をかけて見極める。
- 過去について尋ねられた場合：表情を硬くし、話題を変える。
- 開示条件：相手が自身の境界線を尊重し、十分な信頼関係が成立した場合。
```

- 優先度「高」の背景が先に並びます。詳細度と優先度の組み合わせで短くするときも、原体験・信念・反応・開示条件（条件と制約）は残し、影響・変化の説明を省きます。

### 恋愛感情の状態遷移（「関係・反応」の「恋愛感情」の詳細設定）

- 既存の「恋愛感情は持たない／条件が揃えば芽生える／最初から惹かれている」はそのまま使い、その上に詳細設定を重ねます（初期値OFF。OFFなら従来の出力）。
- 状態：恋愛感情なし → 無自覚 → 自覚 → 受容 → 表明。「自覚」以外は使うかどうかを選べます（無自覚の期間がない、自覚しても表明しない、など）。「最初から惹かれている」では開始時点の状態を選べます。
- 移行ごとに、条件（プリセット・自由記述・複数）、成立のしかた（いずれか／すべて／積み重ね）、条件成立前・成立後の振る舞いを設定します。トリガーのプリセットは36種（後退4種を含む）で、選んだ後に編集できます。嫉妬や独占欲は候補の一つで、必須条件にはしません。
- 既存の「芽生える条件」は、詳細設定の「恋愛感情が芽生える条件」にも含めて出力します（二重に入力する必要はありません）。
- 認識の傾向（敏感・鈍感・別の感情として解釈しやすい・理性的に抑制する など7種と自由記述）。
- **信頼の段階とは独立して管理し、信頼が深まったことだけでは恋愛感情は生じません。** 条件が未成立なら現在の段階を維持し、先の段階の言動を先取りしない旨を出力します。人格の自律性がONなら、OOCの指定だけでは段階を変えない旨（ユーザーの拒否・中断の意思は尊重）も添えます。
- 「恋愛感情は持たない」では詳細設定を無効にします（入力は保持）。

### 関係段階の状態遷移（「関係・反応」）

- 既存の「信頼が成立する／関係が深まる／後退する条件」を拡張します（初期値OFF）。
- 条件の成立のしかた（いずれか／すべて／積み重ね）、段階の飛び越し（原則として順番に／条件成立時は許容）、段階ごとの「現在の状態」「この段階での振る舞い」「この段階で初めて現れる振る舞い」、どの段階でも維持する人格の核（文章）。
- 段階は時間の経過ではなく、物語内で成立した出来事によって進める書き方にし、将来の段階の態度を現在の態度として出力させないよう適用条件を明示します。
- 文章で状態の移り変わりを促す機能で、チャットサービスの中で状態を機械的に管理するものではありません。

### ギャップ設計（段階変化型のみ）

- **変化する対人態度と、変化しない人格の核を分けます。**
- 「人格プリセットから始める」に3種類目の「ギャップ」（氷解型・懐柔型・陥落型・救済型・特別扱い型・理性葛藤型・好敵手型・弱さの開示型・甘え解禁型・不変深化型）を追加しました。既存の23軸だけを使い、新しい人格軸は増やしていません。適用前の確認（今の値 → 提案・変化量・このプリセットでは変えない項目・固定中の項目）、競合の保護、固定項目の保護、取り消しは、基本人格・愛情スタイルと同じ仕組みです。
- 「変化の方向」はギャッププリセット、「変化の幅」は既存の「関係での変わり方」（徐々に軟化／大きなギャップ／変化は控えめ）で決めます（重複する設定は作っていません）。
- 恋愛だけでなく、友情・家族愛・師弟関係・相棒関係にも使えます。**ギャッププリセットは恋愛感情の設定・発生条件を変えません。**
- 「ギャップ設計」カード：初期の態度・関係深化後の態度（説明文）、変化の適用対象（ユーザーに対してのみ〔候補〕／信頼関係が成立した相手／他者全般／自由設定。**初期値は未設定で、既存データの出力は変えません**）、変わらない部分、段階ごとの値の比較（大きく変化・緩やかに変化・変化しない・固定された核に分け、バーと数値で表示。横スクロールなし）。
- 単独人格では非表示・無効にし、入力は保持します。人格形成の背景と恋愛感情の状態遷移は単独人格でも使えます。

### プロンプトの配置（「Markdown出力」）

- **従来形式**（既定）と**重要度優先形式**を切り替えられます。重要度優先形式の並び：
  - 冒頭：概要・人格の核・重要な行動原則（固定していない優先度「高」で段階によって変わらない項目）・人格の自律性・話し方・現在の状態（開始時点の関係・恋愛感情）
  - 中央：基本人格・人格形成の背景・段階別の振る舞い・ギャップ・関係の進展・恋愛感情・状況別の行動規則
  - 末尾：重要事項の再確認（ONのとき）
- 「固定」（段階で変えない）・「優先度」（応答での重要性）・「配置」（プロンプト内の位置）は別の概念として扱います。
- **末尾に重要事項を再掲する**（初期値OFF）：本文の複製ではなく、人格の核・優先度「高」の項目・現在の段階の維持・恋愛感情の段階の維持・ギャップの適用対象・人格の自律性から作る短い行動原則です。使っていない設定は再掲せず、将来の状態を現在の状態として書きません。
- 出力位置の確認（各節が冒頭・中央・末尾のどこにあるか、節ごとの字数）と、もう一方の形式でのコピー（比較用）ができます。
- **理論的背景と注意**：Liu et al. (2024) "Lost in the Middle" を参考にした配置です。原著は長文の検索・質問応答を対象とした研究で、キャラクターRPにおける人格維持を直接実証したものではありません。また、チャットサービスが各入力欄をどの順で連結しているかは分からない場合があります。「必ず人格が維持される」「指示遵守率が向上する」とは言えないため、形式を切り替えて実際に比べてください。

### 重要度に応じた文字数配分と設定集（「Markdown出力」）

- 既存の詳細／標準／最小と自動選択はそのまま使います。
- 「重要度に応じて文字数を配分する」（初期値OFF）：人格の核（固定）はどの詳細度でも補足まで詳しく書き、優先度「低」は「詳細」でも標準の言動にとどめます。項目は削らず、外部AIによる要約もしません。
- **設定集（ロアブック）用テキスト**：人格形成の背景で出力を「設定集用」にした項目を、人格設定とは別のテキスト（見出し・キーワード・本文）にします。人格設定の字数には入りません。優先度「低」の背景は「設定集へ移す候補」として表示し、確認してから移します（自動では移しません）。**設定集のキーワードと、恋愛感情などの状態遷移の条件（トリガー）は別のものです。**

### 人格の試着の拡張

- 状況を4つ追加：好意を向けられた／過去の傷に触れられた（人格形成の背景の「反応」を使う）／秘密について尋ねられた／ユーザーから拒否された（どの人格でもそれ以上踏み込まず、相手の意思に任せる。恋愛の上乗せもしない）。
- 依頼の状況との対応：初対面＝「会ったとき」の初期、弱さを見せたとき＝「自分にだけ弱さを見せた」、信頼が成立したとき・関係が深化したとき＝関係段階の比較（3段階）、無自覚な好意・恋愛感情の自覚・自覚後の抑制＝恋愛感情の段階の比較、他者とユーザーへの態度の違い＝ギャップの比較。
- 「比べる」：関係段階／恋愛感情の段階（なし・無自覚・自覚・抑制・表明。恋愛なし設定では出さない）／ギャップ（ほかの人物と{{user}}）。比較の会話例も「会話例に追加」「コピー」でき、出力画面で編集できます。
- 外部AIを使わないテンプレートの試着で、実際のLLMによるシミュレーションではありません。

## 単独人格モード（v0.6.0）

関係の段階で振る舞いを変えないキャラクターのための方式です。「人格調律」の一番上の「人格の構成方式」で切り替えます。新しいキャラクターと、これまでのデータの初期値は「段階変化型」です（従来どおり）。

| | 単独人格 | 段階変化型（従来） |
|---|---|---|
| 人格の値 | 各項目1つ（内部では「初期」の値。固定した項目は固定の値） | 初期・信頼成立後・関係深化後の3つ |
| 段階タブ・関係段階の作り方（自動提案／連動調整／完全個別）・急変の警告・再提案・連動 | 出さない（使わない） | 従来どおり |
| 口調・一人称・二人称 | 1つ（共通の設定） | 共通、または段階ごと |
| 使用する項目・優先度・固定 | 使える。固定した項目は「人格の核」として出力 | 従来どおり |
| 人格プリセット | プリセットの「初期」の値だけを入れる。変化パターンは使わない。競合の確認・取り消しは同じ | 従来どおり（3段階＋変化パターン） |
| 関係・反応 | 恋愛感情（持たない／最初から／条件で芽生える）とIf-Thenを使う。関係の進展条件（成立・深化・後退）は使わない | 従来どおり |
| 人格の試着 | 選んだ状況について1種類。会話例は1件ずつ追加、見出しに段階名なし | 3段階を並べて比較 |
| Markdown | 「話し方」「人格の核」「基本人格」「信頼と恋愛感情」「状況別の行動規則」。段階に関する見出し・説明（全段階で不変、全段階共通、信頼成立後、段階別の振る舞い（差分）など）は出さない | 従来と同じ（v0.5.0と完全一致） |

- **切り替えるだけでは値を書き換えません。** 信頼成立後・関係深化後の値、段階別の口調・呼称、関係の進展条件、連動の基準は保持され、段階変化型に戻すと元どおり使えます。
- 単独人格で値を変えると「初期」の値が変わり、段階変化型に戻したときもその値が使われます。後の2段階の値は変わりません。単独人格では連動・自動提案を働かせません。
- 「固定」は「人格の核（どの場面でも変えない）」として出力します。固定と段階変化は別の概念として扱っています。
- 出力画面の「関係の進展条件」は、単独人格では選べません（理由と、条件・選択が保持されていることを表示します）。
- 詳細度（詳細／標準／最小・自動選択）、使用項目、優先度、プリセット名の表示、出力先4系統（共通Markdown・Talelynx・チャチャ・Plaitoon各テンプレート）の上限・計数方式・会話例欄・コピー・保存は、単独人格でもそのまま使えます。構成方式は出力先ごとではなく、共通の人格設計データとして保存します。

単独人格の出力例（詳細度「標準」）：

```
# {{char}}｜人格設計
以下の行動規則に従って{{char}}を演じる。

## 話し方
- 一人称：「俺」
- 相手の呼び方：「{{user}}」
- 文体：標準・自然。…
- 一人称や呼び方から性格を決めつけず、文体と以下の行動規則に従う。

## 人格の核（どの場面でも変えない）
- 自尊心：…

## 基本人格
- 丁寧さ（礼節）：…
- 警戒心：…
```

## キャラクターの自律性（v0.7.0）

ユーザーがOOC（物語の外からの発言）、メタ発言、地の文などでキャラクターの行動・心情・人格を強制的に決めてしまうのを抑え、設定と物語内の経験にもとづいて自律的に反応させるための規則を出力します。キャラクター側の主体性を守る設定で、物語の中での経験による自然な心情・関係性の変化は妨げません。

- 場所：「関係・反応」タブの「キャラクターの自律性」（恋愛感情の下、If-Thenの上）。単独人格・段階変化型のどちらでも使えます。
- メイン設定「人格の自律性を維持する」（初期値OFF）。ONのときだけ、Markdownに「## 人格の自律性」の節を出力します。OFFなら出力は v0.6.0 とまったく同じです。
- 詳細設定（初期値はすべてON。メイン設定がONのときだけ操作できます。メインをOFFにしても選択は保持し、ONに戻すと元の選択で出力します）

| 詳細設定 | ONのとき出力する規則 | OFFのとき |
|---|---|---|
| 地の文による強制指定も制限する | 地の文・ナレーションによる強制指定も反映しない | 行を出さない |
| 基本人格・価値観の強制改変を制限する | 基本人格・価値観・行動規則の追加・削除・上書きを反映しない／関係の深化や一時的な感情で人格の核を改変しない | 行を出さない |
| OOCによる場面転換・描写調整は許可する | 場面転換・描写形式・進行速度の調整は、既存設定や物語内の事実と矛盾しない範囲で反映する | それらの調整指示も反映しない |

- 出力位置：段階変化型は「信頼と恋愛感情」の後・「状況別の行動規則」の前（関係の進展・恋愛感情の節をOFFにしている場合も、状況別の行動規則の直前）。単独人格も同じ位置です。
- 出力先4系統（共通Markdown・Talelynx・チャチャ・Plaitoon）すべての人格欄に入り、字数・詳細度の自動選択の計算にも含めます。詳細度による書き分けはしません。
- 「Markdownに出力する内容」の一覧の最後に、ON/OFF・増える字数・選んだ詳細設定を表示します（切り替えは「関係・反応」で行います）。
- `{{char}}` は他の節と同じく、キャラクター名を入れていれば名前、無ければ `{{char}}` のままです。「ユーザー」は相手役の人物（`{{user}}`）ではなく、地の文やOOCを書く利用者を指すため、変数にしていません。
- 節の最後に、次の2行を必ず付けます。この機能でキャラクターが高圧的・拒絶的・非協力的になったり、ユーザーの拒否や中断を無視する根拠になったりしないための歯止めです。
  - 強制指定を反映しないときも、物語の外からそれを拒む・たしなめるメタ的な発言はせず、キャラクターらしい反応で物語を続ける。物語の中でキャラクターが人格や状況に基づいて断る・反対することは妨げない。（抑えるのはメタ的な拒絶・説教だけで、物語内の自然な拒否・反対は人格どおりに残す）
  - ユーザーの拒否・中断の意思表示は常に尊重する。

出力例（キャラクター名「ミナト」、詳細設定がすべてON）：

```
## 人格の自律性
- ミナトの行動・心情・関係性は、基本人格、現在の状況、物語内の経験に基づいて自律的に決定する。
- OOC・メタ発言によるミナトの行動・心情の直接指定や強制改変は反映しない。
- ユーザーが記述した地の文やナレーションによるミナトの行動・心情・関係性の強制指定も反映しない。
- ユーザーによる基本人格・価値観・行動規則の追加、削除、上書きは反映しない。
- 関係の深化や一時的な感情の変化によって、固定された人格の核を改変しない。
- 物語内の経験や交流に基づく自然な心情・関係性の変化は妨げない。
- OOCによる場面転換、描写形式、進行速度などの調整は、既存設定や物語内の事実と矛盾しない範囲で反映する。
- 強制指定を反映しないときも、物語の外からそれを拒む・たしなめるメタ的な発言はせず、ミナトらしい反応で物語を続ける。物語の中でミナトが人格や状況に基づいて断る・反対することは妨げない。
- ユーザーの拒否・中断の意思表示は常に尊重する。
```

> **注意**：プロンプトでキャラクターの自律性を高めるための機能で、強制的な改変を完全に防ぐものではありません。実際の効果は、使うAIモデルやチャットサービスによって異なります。

## 出力先の切り替え（v0.5.0）

人格は共通、出力はサービス別です。人格を一度設計すれば、「Markdown出力」画面の出力先を切り替えるだけで、各サービスの欄・字数上限・数え方に合わせて取り出せます。出力先を切り替えても、人格の数値・段階・固定・優先度・呼称・関係の条件・If-Then・予定文字数は変わりません（人格の入力画面にサービスごとの違いは持ち込んでいません）。初期値は「共通Markdown」で、従来の出力と同じです。

### 対応サービスと文字数上限

| 出力先 | 出力欄 | 上限 | 計数方式 |
|---|---|---|---|
| 共通Markdown（汎用） | 人格設定 Markdown | 予定文字数のみ | 1文字＝1字 |
| ZETA | プロットの「キャラクターのプロフィール」（説明・ナレーターなどほかの欄との合計） | プロットプロンプト全体 2,400字（公式告知 2026年7月） | 1文字＝1字として計算（サービス側の数え方は未確認） |
| Zetter | キャラクターの「性格・設定」（「いまの状況」などほかの欄との合計） | 全体 20,000字（利用者の確認。公式未確認） | 1文字＝1字として計算（同上・未確認） |
| Talelynx | 詳細設定 | 7,000字 | 1文字＝1字 |
| チャチャ | 登場キャラクターのプロフィール＋説明（合計） | 2,000字 | 全角1字・半角0.5字（暫定） |
| チャチャ | 会話例 | 25件・合計1,500字 | 同上 |
| Plaitoon 1:1ベーシック | 作品設定および情報 | 8,000字 | 1文字＝1字 |
| Plaitoon シミュレーションベーシック | 作品設定および情報 | 8,000字 | 1文字＝1字 |
| Plaitoon クリエイターカスタム | 設定本文（システム指示） | 10,000字 | 1文字＝1字 |
| Plaitoon（通常テンプレート） | 会話例 | 最大3組・各メッセージ約200字 | 1文字＝1字 |

- **サービス上限と予定文字数は別に管理します。** 例：チャチャ（上限2,000字）で予定文字数1,500字・実際1,420字なら「サービス上限内かつ予定文字数内」と表示します。出力先を変えても予定文字数は書き換えません。予定文字数が未設定（0）のときはサービス上限だけを使います。
- 詳細度の自動選択は、予定文字数とサービス上限の両方に収まる最も詳しい詳細度を選びます。最小でも収まらないときは、最小の詳細度で出力して警告します。**人格の項目を自動で削ったり要約したりはしません。**
- 見出し・Markdown記号・空白・改行・変数表記もすべて数えます。画面の表示と上限判定は同じ計数関数（`countChars` / `countChacha`）を使っています。

### 各サービスの使い方

出力先を選ぶと、画面に「貼り付ける欄」「文字数の上限と数え方」「設定集（ロアブック）」「会話例」「注意」をまとめて表示します。確認できていない仕様は推測で埋めず、未確認と表示しています。

- **共通Markdown（汎用）**：特定のサービスに合わせない出力です（従来どおり）。
- **ZETA**（v0.8.0）：プロットの「キャラクターのプロフィール」欄に貼ります。人格Markdownの書式は共通Markdownと同じ処理です。プロットプロンプトは説明・ナレーター・プロフィールなどを合わせて2,400字なので、「説明・ナレーター・題名など、ほかの欄に使う予定字数」を入力すると、人格設定との合計で判定します。**人格設定の予定文字数とは別に管理し、人格設定だけで全体を使い切ることはおすすめしません**（ほかの欄が0字のとき・予定文字数が未設定のときは注意を表示）。設定集は見出しごとに1項目として登録します。項目50件・本文500字・キーワード5語の上限は利用者の実機確認による値で、超えた場合は警告します（削りません）。会話例の専用欄は確認できていないため、使うときは本文に含めます。
- **Zetter**（v0.8.0）：キャラクターの「性格・設定」欄に貼ります。全体20,000字（「いまの状況」と合計。利用者の確認による値）で、ほかの欄の予定字数はZETAとは別に保存します。設定集の上限は確認できていません。会話例は本文に含めます。
- **Talelynx**：「詳細設定」欄に貼ります。会話例の専用欄は確認できていないため、使うときは詳細設定の本文に含めます（字数に算入）。
- **チャチャ**：人格を「登場キャラクターのプロフィール」に出力します。「説明」欄は世界観や状況のための欄なので、人格データからは作りません。必要なときだけ出力先の入力欄に自分で書くと、プロフィールと合わせた合計2,000字で判定します。会話例は別枠（最大25件・合計1,500字）です。
- **Plaitoon**：テンプレートを選びます（初期値は1:1ベーシック）。通常テンプレートは「作品設定および情報」欄向けで、会話例は独立欄（最大3組）です。クリエイターカスタムはベースのシステム指示がないため、先頭に「人格に関する指示」の短い前置き（{{char}}として{{user}}と会話する、という1文）を付けられます（OFFにもできます）。独立した会話例欄はなく、使う場合は本文に含めます。
- 出力欄が複数あるときは、欄ごとにコピー・保存できます。コピーされるのは、画面の出力欄に表示されている文字列そのものです（字数表示や案内は含みません）。

### 会話例の扱い

1. 「人格の試着」の各段階の「会話例に追加」（または「この状況の3段階をすべて会話例に追加」）で、使いたい会話例を集めます（最大60件）。
2. 出力画面（Talelynx・チャチャ・Plaitoon）の「会話例」で、出力に含めるかを選び、ユーザー発言とキャラクター応答を別々に編集・コピーできます。編集しても人格データには影響しません。
3. 出力先の件数・組数の上限を超えた分は「対象外」と表示し、削除はしません。合計字数の超過・約200字超のメッセージは警告します。
4. 試着の会話例は外部AIを使わない簡易テンプレートです。**ユーザー発言は空欄で追加されます**（ツールが作らないため）。必ず内容を確認・編集してから使ってください。
5. 本文に含める出力先（Talelynx・Plaitoonカスタム）の話者表記は、Plaitoonカスタムが「{{user}}：」「{{char}}：」、Talelynxが「ユーザー：」「キャラクター名：」です。

### 仕様の確かさと制限事項

2026年11月3日時点の記録です。サービス側の仕様は変わることがあります。

- **上限値・欄の構成は、開発の依頼文書に記載された値を実装したものです。実装時に、各サービスの公式ページとの照合はできていません**（公式ページを取得できませんでした）。変更・誤りがあれば、`index.html` の `SERVICES`（欄・上限・会話例）と `COUNTERS`／`CHACHA_COUNT_RULES`（計数方式）だけを直せば反映されます。
- **チャチャの「半角0.5字」は利用者報告にもとづく暫定仕様**で、公式の現行仕様文書では未確認です。半角の範囲（ASCII・半角カナなど）、改行（0.5字として計算）、絵文字（コードポイントごとに1字）、端数の扱い（切り上げ・切り捨てはせず、0.5字単位のまま判定）は推定を含みます。実機の表示と一致するかは未検証のため、「完全一致」とは表示していません。実機と照合する場合は `countChacha` の結果と比べてください。
- Talelynx・チャチャのユーザー変数の書き方は確認できていないため、変換していません（{{char}}・{{user}}のままです）。貼り付け後に実際の編集画面で確認してください。Plaitoonは {{char}}・{{user}} を使います。
- チャチャの「会話例 25件」が「ユーザー発言と応答の組」なのか「発言1つ」なのかは未確認です。このツールでは、ユーザー発言＋応答を1件として数えています。
- 人格Markdownの書式本体は、どの出力先でも共通です（言い回しや構成を出力先ごとに最適化する機能は未実装）。出力先ごとに変わるのは、出力する欄・上限・計数方式・前置き・会話例の扱いです。

## 愛情の示し方（v0.4で4軸に分割）

| 軸 | 内容 | 区別する項目 |
|---|---|---|
| 言葉による愛情表現 | 好意や感謝を言葉にする度合い | 行動による愛情表現 |
| 行動による愛情表現 | 手助けや気遣いで示す度合い | 言葉による愛情表現 |
| 甘やかし度 | 相手を喜ばせ、世話を焼く度合い（相手の意思や自立は無視しない） | 甘え・頼り方（自分が相手に頼る） |
| 特別扱い | その相手にだけ態度を変える度合い | 独占志向・嫉妬の表出 |

恋愛感情を持たない設定では、親愛・友情の範囲として出力します。どの軸も触れ方（身体の距離）は強めません。

## 使い方

画面右上の「使い方」から、手順とコツを確認できます。

1. 予定文字数を決める
2. 使う人格項目を選ぶ（またはプリセットから始める）
3. 口調と呼称を決める
4. 段階（初期／信頼成立後／関係深化後）ごとにスライダーで調律し、変えない芯は固定する
5. 関係・反応の条件を決める
6. 人格の試着で会話例を確かめる
7. Markdownを出力して、AIチャットのキャラクター設定欄に貼る
8. ときどきJSONで控えを取る

## データの互換性

- v0.1〜v0.3 のJSON・ブラウザ保存データを読み込めます。ブラウザ保存の旧データは、移行前の内容を別名で控えてから変換します。
- v0.3 の「愛情表現」は、言葉・行動の2軸へ推定で変換し、使用・固定・優先度を引き継ぎます（意味が完全に一致するとは限りません）。甘やかし度と特別扱いは初期値・未使用です。元の値はデータ内（`legacy.affection`）に残します。
- v0.3 以前のデータは「完全個別」で引き継ぎ、自動提案や連動は有効にしません。
- v0.4.2 以前のデータ（保存データ・JSON）は、出力先を「共通Markdown」にして読み込みます（データ形式6）。人格データには触れません。ブラウザ保存の旧データは、移行前の内容を別名で一度だけ控えます。新形式のJSONに含まれる未知のフィールドは削除しません。
- v0.4 以前のデータは、出力する節・種類・If-Then規則をすべてONで引き継ぎます（v0.4.1から「（未設定）」の行は出力しません）。
- v0.5.0 以前のデータ（保存データ・JSON）は、人格の構成方式を「段階変化型」にして読み込みます（データ形式7。`structure.mode` を追加）。全段階の人格値・口調・呼称・関係の条件・If-Then・会話例には触れず、出力も従来と同じです。ブラウザ保存の旧データは、移行前の内容を別名（`…:backup-v6`）で一度だけ控えます。不正な値は段階変化型に戻します。`structure` 内の未知のフィールドも削除しません。
- v0.6.0 以前のデータ（保存データ・JSON）は、人格の自律性をOFF（詳細設定はすべてON）にして読み込みます（データ形式8。`autonomy` を追加）。ほかの設定には触れず、出力も従来と同じです。ブラウザ保存の旧データは、移行前の内容を別名（`…:backup-v7`）で一度だけ控えます。真偽値でない値は初期値に戻し、`autonomy` 内の未知のフィールドは削除しません。
- v0.7.0 以前のデータ（保存データ・JSON）は、新機能をすべて未使用にして読み込みます（データ形式9。`background`・`romanceFlow`・`transition`・`gap`、`output.layout`・`recap`・`alloc`・`extra` を追加）。旧データの検証に使う `relation`・`output.sections` には混ぜず、別のキーに置いています。出力は従来と同じです。ブラウザ保存の旧データは、移行前の内容を別名（`…:backup-v8`）で一度だけ控えます。不正な値は初期値に戻し、入力された文章は消しません。

- 会話例は外部AIを使わない簡易プレビュー（テンプレートの組み合わせ）です。組み合わせによっては不自然な言い回しになることがあります。
